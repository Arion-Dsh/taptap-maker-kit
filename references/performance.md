# 性能

先在目标设备和可复现场景记录基线，确认瓶颈属于 Lua 更新、绘制提交、GPU、资源加载、内存或网络。没有数据时先加轻量计数和耗时采样，不做大规模重构。

## 可见性

- 先查当前 Maker 渲染、相机、图形 API、类型声明和相关示例。已有引擎裁剪时复用，不再逐对象重复判断。
- 即时或自定义绘制先按相机可见范围筛选。使用对象包围范围和进入/退出余量，避免边缘漏绘或闪烁。
- 对象很多时先用引擎空间查询、网格或区块取得候选；小场景有余量时不强加空间索引。
- “存在、参与规则、需要更新、需要绘制”是不同状态。离屏可停止绘制，但计时、规则和再次入屏状态必须正确。
- `UI.SafeAreaView` 只约束 UI Layer；World Layer 始终按完整 Viewport 判断可见性。

## 更新与资源

- 可见交互对象正常更新；近距离非关键工作可降频；远距离对象分批、低频或事件驱动，避免同帧集中补算。
- 渲染裁剪只影响客户端表现。服务端模拟和网络权威不依赖客户端相机；网络兴趣范围另行设计。
- 绘制时不重复加载或解码资源。只有分析证明有收益时才引入对象池、图集、批处理或自建空间索引。
- 卸载对象或区块时解除事件、定时器和资源引用；隐藏不等于释放。

## 验证

比较优化前后的帧耗时、长帧、总对象、候选对象、可见对象和实际更新对象。能够取得时再记录绘制调用、Lua 内存和加载耗时。

覆盖相机静止、快速移动、缩放、传送、对象密集和最低目标设备；检查屏幕外无用绘制、边界不闪烁、离屏规则正确、多人结果不受客户端相机影响。
