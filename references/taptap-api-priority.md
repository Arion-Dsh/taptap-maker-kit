# Maker API 与存储

## 查证顺序

找到足够证据后停止，不读取无关文档：

1. 当前 `game/AGENTS.md` 与 Maker MCP 状态或资源。
2. `engine-docs/lua-scripting-guide.md` 和当前能力对应的 recipe。
3. 对应 API 文档与 `.emmylua` 声明。
4. `urhox-libs/` 的高层封装。
5. `examples/api-index.md` 指向的相关示例。

现有业务代码只说明当前兼容需求，不能单独证明 API 正确。网页仅在本地资料不足且项目规则允许时补充；不能用 TapTap Developer Center 或其他平台文档替代 Maker 文档。

## 示例使用

只读取当前功能相关的示例，并遵守 `game/AGENTS.md` 规定的数量。可以参考生命周期、组件组合和 API 调用；不要复制示例玩法、素材、数值或全局状态。示例冲突时，以托管规则、MCP 和当前文档为准。

## API 边界

- Maker 调用集中在 `Runtime`、`Input`、`Presentation`、`Persistence`、`Network` 或 `Platform`；领域规则不持有 Maker 全局对象。
- 优先使用当前文档推荐的高层封装，再考虑已确认的底层 API；不复制平行的 UI、输入、网络、存储或生命周期系统。
- 使用前确认运行端、初始化条件、参数和结果、错误与取消、资源释放及测试替身。缺少关键证据时标为“待查证”。
- 不编造方法、事件、字段、枚举或资源路径；不在 `require` 时产生外部副作用。

## 云存储路由

先读取 `.project/settings.json`，再根据是否存在实时共享状态或服务端权威判断：

| 场景 | 存储 | 调用端 |
|---|---|---|
| 单机存档、设置、单机异步全服榜 | `clientCloud` | 客户端 |
| 实时联机、匹配、合作、对战、公共世界 | `serverCloud` | 服务端 |
| 多人项目中的个人进度、经济、背包、赛季榜 | `serverCloud` | 服务端 |
| 可删除的设备缓存或开发数据 | `File` | 客户端本地 |

排行榜包含多个用户不等于实时多人。虽然 `clientCloud` 可在 Client 运行端存在，多人数据仍只能走服务端 `serverCloud`。同一数据不得双写，也不得在两种云存储和 `File` 之间静默降级。

多人客户端只提交意图；服务端从认证连接取得用户身份，校验状态后写入权威数据。客户端不能决定最终奖励、货币、伤害或物品归属。

单机升级多人时单独设计版本迁移。未确认安全迁移通道前，不假定服务端能读取原 `clientCloud`；云调用失败应返回明确错误或进入有界重试/只读状态。
